## Findings & Resolutions

### 1. Removal of Destructive Statements in `database.sql`
- **Issue:** `database.sql` contained `TRUNCATE TABLE ... CASCADE;` across 11 transactional tables.
- **Resolution:** Removed the destructive `TRUNCATE` block. All `INSERT` statements in `database.sql` now use `ON CONFLICT (id) DO UPDATE`, making the seed file purely additive, idempotent, and non-destructive.

### 2. Prevention of Demo Reports in Fresh Deployments
- **Issue:** Flyway migration `V11__seed_community_reports.sql` inserted 4 demo reports, 4 evidence entries, and 7 timeline records on fresh database initialization.
- **Resolution:** Cleared demo inserts from `V11__seed_community_reports.sql`. Fresh deployments now create schema with 0 demo reports naturally, removing any requirement for post-migration deletion.

### 3. Administrator Authentication & `ADMIN_PASSWORD` Inspection
- **Verification:**
  - Admin accounts (`mwalb66`, `admin`, `superuser`), BCrypt hashes (`$2a$10$...`), active statuses (`is_active = TRUE`), roles (`ADMIN`, `STUDENT_LEADER`), and leader assignments were verified intact.
  - Inspection of `DataSeeder.java` confirms `ADMIN_PASSWORD` is read from the environment at startup. If provided, `DataSeeder` updates admin account `mwalb66` (`raphaelfrank720@gmail.com`) with the BCrypt hash of `ADMIN_PASSWORD`. If omitted, it falls back to `"CAMPNAV1111()"`.
  - No passwords or credentials were changed or exposed in source files.

### 4. Mzumbe University Scope Check
- **Discrepancy Report:** Codebase, frontend Compose UI (`UniversitySelectionScreen.kt`), drawable assets (`logo_udsm`, `logo_udom`, `logo_must`, `logo_sua`), database schema, and seed data were inspected. Mzumbe University is **NOT** included in current project requirements. The system supports 4 universities (UDSM, UDOM, MUST, SUA). No missing locations were invented.

### 5. PostgreSQL Auto-Increment Sequence Verification
- **Verification:** `database.sql` resets all 18 PostgreSQL auto-increment sequences using `SELECT setval('<seq_name>', COALESCE((SELECT MAX(id) FROM <table_name>), 1))`. Inserted a test report into the disposable staging database post-seed import; primary key ID `2` was generated cleanly without PK collisions.

### 6. Security & Build Artifact Scan for GitHub
- **Issue Found:** Missing `.gitignore` in `backend` resulted in tracked compiled build outputs (`backend/build/`), Gradle caches (`backend/.gradle/`), and runtime log files (`app_boot.log`, `server.log`, `startup.log`, etc.).
- **Resolution:**
  1. Created root `.gitignore` and `backend/.gitignore`.
  2. Executed `git rm -r --cached` to untrack all build directories, class files, jar files, and log files from the git index.
  3. Scanned repository for private keys (`.pem`, `.key`, `.jks`, `.p12`); none were found.
